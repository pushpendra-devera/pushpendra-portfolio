architecture: "The core is a resumable LangGraph state machine backed by SQLite: discover -> canonicalize -> dedupe -> score -> select -> tailor -> human review interrupt -> persist -> prepare -> assisted apply -> human confirmation. LangGraph is used for durable checkpointing and interruption, not as a wrapper around every model call: model calls go through an application-owned provider abstraction over native Anthropic/OpenAI/NVIDIA-NIM SDKs, keeping scoring weights, safety rules, and state transitions in deterministic application code. Fit scoring mixes four model-judged categories (required skills, tech stack, experience level, preferred skills) with five deterministic ones (seniority, location, remote preference, employment type, salary); the model never sees the category weights, and missing categories are removed with weights renormalized rather than penalizing a posting for omitting a field. The Electron desktop app splits a sandboxed React renderer (no Node.js, filesystem, or secrets access), a narrow typed preload bridge, Electron main, and isolated utility worker processes for the agent host, run execution, assisted-apply sessions, and Naukri login/handoff, so a crash or cancellation in one worker doesn't take down the shell. Application status transitions run through a centralized state machine where 'submitted' is terminal and reachable only via explicit human confirmation, and applicant profile/resume data is content-addressed so an edited resume can't be uploaded under an earlier approval."

## Overview

I built AI Job Agent as a local-first, human-supervised system for the repetitive
parts of a job search. It discovers roles from supported applicant-tracking
systems, records where every posting came from, evaluates fit, prepares grounded
application material, and assists with form filling. It deliberately stops before
submission: I review the generated material and the actual browser form, click
Submit myself, and confirm the outcome separately.

## Problem

Job searching involves a lot of repetitive, lower-judgment work: finding
postings across scattered ATS boards, comparing them against a profile, and
filling the same categories of form fields over and over. None of that requires
a human in the moment. But a few steps genuinely do: deciding whether a claim on
a resume is accurate, answering legally consequential or demographic questions,
and clicking Submit. The design goal was to automate the first category
aggressively and keep the second category strictly out of the agent's hands,
not as a policy statement, but as things the code is structurally incapable of
doing (no submit method exists on any ATS adapter; demographic questions are
never auto-answered).

## Why these projects are grouped

These repositories were created as focused React Native exercises and had no
README files. I reviewed the source of every screen and API module to recover
what was actually implemented. Grouping them keeps that work visible while
making a clear distinction between exploratory builds and the production case
studies elsewhere in this portfolio.

## Repository-by-repository

### BostonResearch

A research-news interface with a splash screen, three-slide animated onboarding
carousel, login UI, and a dashboard containing horizontal and vertical story
feeds. The committed navigator includes the Dashboard route; the remaining gap
is functional authentication: the controls are presentation-only and the feed
is static mock content.

### Parking-lot iterations

Two versions explore the same three-screen flow: choose lot capacity, assign a
free space to a plate number, then calculate a time-based charge before
releasing the slot. The later version adds input validation, duplicate-plate
checks, a live free-space count, and moves shared state from navigation params
to React Context. Its “Pay” request targets a testing endpoint, not a real
processor.

### NewsPost

A two-screen Hacker News client backed by Algolia's newest-story endpoint. It
loads more pages at the end of the list, runs a delayed refresh, and filters the
loaded data by title or author. The detail screen remains a raw JSON view.

### Asteriod

A NASA NeoWs browser with search-by-ID and random-selection paths. Both navigate
to a shared details screen showing the object name, ID, JPL URL, and hazard flag.

### Map-Question

A location-services experiment that requests foreground permission, obtains GPS
coordinates, reverse-geocodes them with MapQuest on an interval, and displays a
running address list. The interval lifecycle and stale-state append logic need
correction before this should be treated as a finished app.

### React-Native-TImer

A single-screen countdown interaction with minute and second picker wheels,
start/stop control, an MM:SS display, and automatic reset at zero.

### Pokemon

A PokeAPI browser with name search, a three-column sprite list, and incremental
loading in groups of 20. Selecting or searching for a Pokémon fetches its full
record and navigates to a detail route; the current detail UI displays that
payload as raw JSON. The source lives on a nonstandard branch named `Pokemon`
and includes generated Expo cache files, which should be cleaned before using
the repository itself as a code sample.
